# Проверка короткого промпта

2026-11-02. Решение: **не заменять промпт на уже обученном адаптере**. Сокращение даёт измеримый выигрыш времени в малом обучающем пилоте, но проверенные варианты ухудшили качество при прямой замене. Качество после полноценного обучения с короткой инструкцией не измерено.

## Качество на одинаковых весах

Веса: Day9 iteration-1, обученные с исходной русской инструкцией. Восемь заранее зафиксированных valid-входов в smoke-inputs.jsonl, одинаковые greedy/max256. Final не использовался.

| Вариант | Токены system | Точные ответы | Невалидные по контракту |
|---|---:|---:|---:|
| Исходный русский | 1133 | 5/8 | 0 |
| Короткий английский v2 | 764 | 3/8 | 3 |
| Короткий русский | 955 | 2/8 | 0 |

Английский v1 был остановлен досрочно: систематически пропускал clarification_reason. Его исходные инструкции и данные сохранены в v1/, частичные ответы — evaluation/iteration-1-valid/. В v2 добавлен явный шаблон всех семи ключей. Остались неправильная сумма без десятичных знаков, будущая дата, заполненные поля при missing_context. У русского варианта форма ответов корректна, но смысловые поля чаще не совпадают с эталонами.

Набор из восьми случаев мал; это основание отклонить прямую замену, а не доказательство невозможности обучить модель с короткой инструкцией. Английский вариант также меняет язык, поэтому падение качества нельзя приписать только длине.

## Время обучения

Четыре отдельных запуска в порядке long → short → short → long. Каждый: одни и те же четыре входа/ответа, исходный адаптер Day7 iteration-4, batch1/accum4, один optimizer update. Параметры, хеши и сырые метрики сохранены в benchmark/. Это другие веса, чем в проверке прямой замены выше: для времени воспроизведена стартовая конфигурация пилотов Day9.

Время обучающих шагов и сохранения, без отдельно измеренной validation: **88,12 с** в среднем для длинного и **56,36 с** для короткого английского. Сокращение **36,0%**, отношение скоростей около1,56. Расчёт: benchmark/comparison.json.

Это маленький пилот, включающий компиляцию и сохранение. Его нельзя выдавать за время полной эпохи или обещание такого же ускорения. Скорость русской версии отдельно не измерялась. Задержка inference менялась между последовательными запусками; ускорение пользовательского запроса не заявляется.

## Продолжение Day9

Длинный iteration-1 уже завершился за67,03мин: valid41/63 против38/63 у исходного ученика; teacher63/63. Ложных расходов5→5, новых опасных valid-ID нет. Чтобы не тратить ещё час на повтор длинного режима, второй seed пропущен; результат не считается подтверждённым повтором. Выбранные веса зафиксированы до final. finish_existing.py выполняет финальное сравнение и сохраняет общий отчёт автоматически.

Для следующего эксперимента с короткой инструкцией потребуется обучение с ней и полная valid-оценка. В этом исследовании такая полная эпоха не выполнялась; четыре микропрогона служат только измерению времени.
